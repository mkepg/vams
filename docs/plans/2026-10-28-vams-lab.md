# VAMS Lab Implementation Plan

**Goal:** A `/lab` page where a student writes a whole 2D GLUT program, compiles it on a Cloud Run service within the always-free allowance, and runs it in a floating window that draws what FreeGLUT draws.

**Architecture:** The compile service runs Emscripten's clang in a container and returns the student's code as a small WebAssembly side module. The shared parts (libc, libc++, stb_image, the Windows extras and the bridge to the GL runtime) are one main module, built once per toolchain version and served from Cloudflare. The program runs in a Web Worker with its own real `glutMainLoop`: it blocks on `Atomics.wait` for events, typed input and timers, and draws with a TypeScript software rasteriser into a shared framebuffer that the page copies to the screen on each animation frame. The page is a Preact route with a CodeMirror 6 editor, a foldable Compiler and Console log, and a stage holding the program window.

**Tech Stack:** Emscripten (clang, wasm-ld, dynamic linking), Node 24 on Cloud Run, Firestore over REST, a Cloud Run function for the billing switch-off, Cloudflare Pages Functions and KV, Preact, Zustand, CodeMirror 6, idb-keyval, fflate, Vitest + happy-dom, Playwright.

**Spec:** [docs/specs/2026-10-28-vams-lab-design.md](../specs/2026-10-28-vams-lab-design.md). Its owner decisions and the calls it marks as already made are binding. Where this plan makes a call the spec left to the builder, it says so under "Calls this plan makes".

## Calls this plan makes (left to the builder by the spec)

1. **Toolchain: Emscripten, pinned to one version** in `lab/toolchain/EMSDK_VERSION` (start with `4.0.10`; Task 1 confirms the image pulls). The student's code is linked as a `SIDE_MODULE`; everything shared is in one `MAIN_MODULE`. This is what keeps a compile's download under 100 KB with `<iostream>` in it. Task 1 is a gate: if dynamic linking fails a check there, fall back to static linking with `-Oz` and record the measured sizes in the ledger before going on.
2. **GL runtime: a software rasteriser in TypeScript** (`src/shared/lib/gl-raster/`). WebGL has no wide lines or stipple, so emulation would be needed anyway, and a rasteriser written to the GL 1.5 specification's rules can be tested in Vitest without a GPU. The rasteriser has no imports outside its folder, so the editor can use it later.
3. **`glutMainLoop` really loops, in the worker.** Atomics.wait is allowed in a worker, so the program blocks the way a native one does: on events, typed input, timers and buffer swaps. Nothing unwinds and Asyncify isn't needed.
4. **Drawing reaches the screen through a shared framebuffer,** not an OffscreenCanvas: the worker writes RGBA into a `SharedArrayBuffer` and bumps a frame counter, and the page copies it to a 2D canvas on its next animation frame. `glutSwapBuffers` waits for the page to take the frame, as vsync does on a lab PC. This replaces the spec's OffscreenCanvas wording and keeps its purpose: a runaway program never blocks the page, and ✕ is `worker.terminate()`.
5. **The main module is served from Workers KV** through a Pages Function at `/lab-runtime/<version>/<file>`, uploaded by `scripts/lab/publish-runtime.mjs`. It's generated output, so it can't be committed, and Pages builds can't run Emscripten.
6. **The 2D set's single source is the bundled headers** in `lab/include/`. What they declare is allowed. `lab/include/vams_rejected.h` marks each rejected name `__attribute__((unavailable(...)))` with its replacement text. Tests parse the headers.
7. **The compile service is TypeScript run by Node 24's type stripping** (`node:24-slim`), with no runtime npm dependencies. Firestore and the metadata server are called with `fetch`.
8. **A daily ceiling of 4,000 compiles** sits beside the monthly counter, so writes stay under Firestore's free 20,000 a day (at most 3 writes per compile) even under abuse. When the day is full, Run shows the resting message with "tomorrow" in place of "the 1st".
9. **Reference images come from the course toolchain** (`~/repos/THESIS/openglcpp/mingw32`, g++ 11.3 with FreeGLUT and GLEW, as on a lab PC) rather than MSYS2. The capture shim reads the back buffer with `glReadPixels`, so the image doesn't depend on screen scaling.
10. **Share links** are `/s/<id>`. The share function stores a payload with `kind: 'lab'`, and the page that opens `/s/<id>` sends Lab payloads to `/lab?share=<id>` with a full page load.

## Review Focus

1. **A program that never returns from `display()`, or prints in a tight loop:** the page stays responsive, ✕ ends it, and the Console keeps only the last 5,000 lines (pinned in Task 11, `BB-LAB-31`).
2. **Reaching `/lab` by a client-side link, or from the service worker's cache:** without isolation `SharedArrayBuffer` doesn't exist. The header link does a full load, the service worker never answers `/lab`, and the page checks `crossOriginIsolated` and reloads once if it's false (pinned in Task 12, `BB-LAB-36`).
3. **Paths in student code:** `"C:\\Users\\x\\Desktop\\skibidi.png"`, `"./Input.txt"`, `"input.txt"` when the list has `Input.txt`, and a name not in the list. The basename is matched case-insensitively, as Windows does, and the missing name is reported in the Console (pinned in Task 11, `BB-LAB-27`).
4. **Includes that try to read the server:** `#include "/etc/passwd"`, `#include "../../proc/self/environ"`, `#include MACRO`, `__has_include`, `#embed` and `#pragma` forms. Each one is refused before clang runs, and no response contains a byte of another file (pinned in Task 3, `SEC-LAB-01..03`).
5. **A whole lab room pressing Run in one minute from one IP address:** 40 compiles all succeed, retries show the busy line, and none hits the per-IP ceiling (pinned in Task 7's load check, `SEC-LAB-09`).

- Create: `src/shared/lib/gl-raster/{framebuffer,clip,points,lines,polygons,fragment}.ts`, `src/shared/lib/gl-raster/index.ts`, `tests/algorithm/gl-raster.test.ts`

**Interfaces:**
- Produces:
  - `createFramebuffer(width: number, height: number, buffer?: SharedArrayBuffer): Framebuffer` (RGBA8, row 0 at the bottom, as in GL).
  - `rasterPoint(fb, v: WinVertex, state: RasterState)`, `rasterLine(fb, a, b, state)` and `rasterTriangle(fb, a, b, c, state)`.
  - `WinVertex = { x: number; y: number; z: number; w: number; color: RGBA; tex?: [number, number] }` in window coordinates.
  - `RasterState` holds `pointSize`, `lineWidth`, `stipple: { factor; pattern; enabled; counter }`, `polygonMode: { front; back }`, `cullFace`, `frontFace`, `shadeModel`, `blend: { enabled; src; dst }`, `scissor`, `texture: TextureUnit | null` and `envMode`.
- Rules (from the OpenGL 1.5 specification, section 3):
  - Points are size × size squares centred on the point. Odd sizes centre on the pixel and even sizes on the pixel corner (3.3).
  - Width-1 lines use diamond-exit (3.4.1). The last pixel of a segment isn't drawn, except where a strip's segments meet. Wide lines are drawn as `width` pixels in the minor axis direction, not as rectangles (3.4.2).
  - The stipple counter resets at `glBegin` and for every `GL_LINES` segment, but not between `GL_LINE_STRIP` segments, and advances once per pixel (3.4.2).
  - Polygons use the top-left rule with pixel centres at `.5`. `GL_FLAT` takes the colour of the provoking vertex from Table 2.12: the last vertex of each triangle and quad, the first of a `GL_POLYGON` (2.14.7). `GL_SMOOTH` interpolates perspective-correctly, which in 2D is linear.
  - `GL_LINE` and `GL_POINT` polygon modes draw edges and vertices with the line and point rules.
